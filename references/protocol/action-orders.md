## §2 5 段式输出结构（动作维度主 · 严格分离）

### 2.1 标准结构（5 段式 · V1.6.1 移除 D 折叠段）

```
【行动要项】①策略 ②方向 ③优先级（护栏）
【事态导航】查风险 → 机遇链 → 查要因 → 做多少
【危机沟通】3T × 3 列表 交叉表（6 列）
【行动措施】动作阶段 × 4×N 维度
  └─【后续计划】(L2-L4 每层核心一句话+责任层)
【双归零】按动作阶段展开
(可选)【定位探针】V8.2 新增 · 默认折叠 · 触发词 `展开定位`
  - 粒度门槛：D ≥ 4（中度及以上）
  - 特征开关：多链（多工序/多客户）/ 隐蔽（F-探测度 ≥8）/ 复发（同类 ≥2）
  - 展开深度：半展开（四面+多链）/ 全展开（16 格+定深+取物）
  - 重度无特征 → 半展开（避免过度分析）· 用户强制可全展开
  - 诊断结论 + 导航（V8.2 增强）：
    特征→阶段映射（多特征并存优先级：复发 > 隐蔽 > 多链）：
      | 特征 | 导航阶段 |
      |------|---------|
      | 多链 | AO-2（选型）|
      | 隐蔽 | AO-1 围堵要点 + AO-3（检测纠正）|
      | 复发 | AO-4（体系预防）|
      | 重度复合 | AO-2 + AO-3（全链）|
      | 无特征（档位兜底）| 中度→AO-2 · 重度→AO-2+3 |
  - 复杂粒度检阅（V8.2 增强）：超复杂（多链特征≥2 或 16 格≥4）→
    分层检阅 L1 概览（默认可见）→ L2 单链深入 → L3 逐格检视（§6 折叠）
  - **决策桥（V8.2 增强）**：探针在复杂场景（D≥4+特征）下升级为 **§4→AO 卡的决策输入**——
    §4 定范围（D 档位→阶段链）· 探针定方向（特征→阶段精化）· 画像填 AO 卡（6 字段）
    探针输出 → AO 卡字段映射：
      | 探针输出 | AO 卡落点 | 协议引用 |
      |---------|----------|---------|
      | 导航阶段 | §4 阶段精化（特征→AO 方向）| §2.1→§4 |
      | 组织层定位 | §5 责任层确认/校验 | §2.1→§5 |
      | 16 格落点 | AO-3 措施范围界定 | §2.1→§1.3 |
      | 多链起点 | AO-2 方案维度（3A5WHY 起点）| §2.1→3a5why |
      | 取物（工具格）| AO 卡核心工具列填充 | §2.1→§1 |
      | 定深（L1-L4）| 双归零展开版本（简/完整/总结）| §2.1→§3.4 |
```

### 3.1 危机判定（D1+D2+D3）

| 维度 | 内容 |
|------|------|
| D 总分 | D1+D2+D3+探测溢价 = 0-10（V8.2：FMEA 维度化）|
| D1 传播性 | 1-3：1=单点 / 2=小范围 / 3=大范围或平台扩散 |
| D2 严重性 | 1-3：FMEA S 映射（S 7-10→3 / S 4-6→2 / S 1-3→1；无 S 输入时按 1=体验不满 / 2=客诉退单 / 3=安全合规品牌）|

## §8 QCM-Infoseek 归因协议（V7.0 新增 · 5 维触发信号）

### 8.1 触发条件

- 5 维触发信号 ≥2 维度失败 → 调用 Infoseek 归因
- 5 维：行业 / 危机类型 / 工具 / 标准 / 大师

### 8.2 接口契约

```yaml
input_schema:
  required:
    - unparsed_query (string)
    - qcm_failure_dimensions (array)  # 5 维触发信号
  optional:
    - industry_hint (string)
    - mds_fields (object)
output_schema:
  required:
    - attribution_id (string)
    - anchors (array)
    - confidence_score (int 0-100)
    - matched_qcm_form (enum)  # case_application/decision_card/assessment_report/quick_response
  optional:
    - fusion_report (string)
    - suggested_tools (array)
    - qcm_ingestion_plan (object)
side_effects:
  - 归因记录写入 governance.md 调研历史
  - idempotent: false
```

### 8.3 调用流程

1. 检测 5 维触发信号
2. 封装参数（unparsed_query + failure_dimensions）
3. 调用 Infoseek 5 端点（anchor_discovery + anchor_score + research + entity_profile + conflict_detection）
4. 评估置信度
5. QCM 归因映射 → 4 形态路由
6. 输出 + 缺口标注

### 8.4 入库策略

- ≥70：写入主库（人工审核）
- 40-69：归因历史（不污染）
- <40：终止（不引用）

### 8.5 降级协议（V8.0+ 新增 · Infoseek 未安装/不可用兜底）

> **核心原则**：Infoseek 是 **optional 依赖**，不是 required。QCM 归因能力在任何环境下可用，未安装时逐级降级并显式标注。

#### 8.5.1 降级链（L0 → L1 → L2 → L3）

```
QCM 归因触发（5 维 ≥2 失败）
  ↓
[L0] Infoseek 可用探测（_probe_infoseek）
  ├─ YES → Infoseek research_v3（完整多源归因 · 置信度 ≥70）
  └─ NO  → [L1] QCM 本地 corpus 检索
            ↓
            [L1 命中 ≥2 相关源?]
              ├─ YES → 本地 corpus 归因（标注 [local-only]）
              └─ NO  → [L2] Web 搜索降级（LLM Router 调外部搜索）
                        ↓
                        [Web 可用?]
                          ├─ YES → Web 结果 + 标注 [unverified]
                          └─ NO  → [L3] 纯 QCM 协议推理
                                    标注 [unverified][no-external-source]
                                    写入 gap_tracker.md（待 M4 批量回源）
```

#### 8.5.2 探测机制（_probe_infoseek）

- 探测路径：`$INFOSEEK_ROOT/scripts/infoseek_mcp_server.py --version`
- 返回枚举：`available` / `not_installed` / `timeout`
- 超时阈值：3 秒（不阻塞主流程）
- 探测结果缓存：30 分钟（避免频繁 subprocess 启动）

#### 8.5.3 输出契约扩展（§8.2 output_schema 补充）

```yaml
output_schema:
  required:
    - attribution_id (string)
    - anchors (array)
    - confidence_score (int 0-100)
    - matched_qcm_form (enum)  # case_application/decision_card/assessment_report/quick_response
    - infoseek_status (enum)   # 🆕 available / not_installed / timeout / partial
  optional:
    - fusion_report (string)
    - suggested_tools (array)
    - qcm_ingestion_plan (object)
    - degradation_path (enum)  # 🆕 L0_infoseek / L1_local / L2_web / L3_protocol
    - warning (string)         # 🆕 未安装时的显式提示
```

#### 8.5.4 降级标注规则

| 降级路径 | 标注 | warning 内容 |
|----------|------|--------------|
| L1_local | `[local-only]` | "Infoseek 未安装，归因基于 QCM 本地 corpus" |
| L2_web | `[unverified]` | "Infoseek 未安装，Web 结果未经多源交叉验证" |
| L3_protocol | `[unverified][no-external-source]` | "建议安装 Infoseek 后执行 M4 批量回源" |

#### 8.5.5 知识闭环（缺口回填）

- L3 降级结果写入 `gap_tracker.md`（status=pending_infoseek）
- Infoseek 安装后：M4 批量回源（按 gap_tracker 记录逐条补调研）
- 回填完成：gap_tracker status → resolved
- 健康指标：缺口回填率 ≥80%（季度）

#### 8.5.6 契约一致性

- **无论降级到哪级**，output_schema 结构一致（infoseek_status + degradation_path 显式标注）
- 降级不改变 4 形态路由（case_application/decision_card/assessment_report/quick_response）
- 降级不改变 §8.4 入库策略（置信度阈值不变）
- Infoseek 可用时自动升 L0（渐进增强）

## §10 Infoseek 收敛协议（V8.0 新增 · 逐级收敛）

### 10.1 收敛级别

- Level 1：协议层规则未覆盖 → 基础调研
- Level 2：调研结果模糊 → 收敛追问
- Level 3：收敛追问模糊 → 深度追问

### 10.2 收敛深度限制

```yaml
max_depth: 3
max_query_per_level: [1, 3, 5]
max_total_query: 9
max_tokens_total: 15000
timeout_total: 90s
confidence_threshold: 70
```

### 10.3 终止条件

- 置信度 ≥70 → 归因成功
- 调研深度 = 3 → 强制终止
- 5 维全失败 → 终止
- 超时 → 降级

### 10.4 案例/场景对 Infoseek 调研的影响

- 高置信度归因结果 → 不入库（避免污染）
- 跨多个相同归因 → 触发入库建议（人工审核）

## §11 热词与末端触点协议（V8.0+ 新增 · QCM 颗粒度 4 层 + L4 末端触点收敛）

### 11.1 QCM 颗粒度与收敛级别

| QCM 颗粒度 | 含义 | Infoseek 收敛级别 |
|----------|------|-----------------|
| L1 行业 | 行业大类 | Level 1（深度 1）|
| L2 工艺 | 工艺类别 | Level 1-2（深度 1-2）|
| L3 工序 | 工艺环节 | Level 2（深度 2）|
| **L4 末端触点** | **工序内失效点** | **Level 4（深度 2-3）** |

### 11.2 热词体系

- L1 行业热词（动态 · 每月）
- L2 工艺热词（动态 · 每 2 周）
- L3 末端触点热词（动态 · 每周 · V8.0+ 核心）
- 来源：案例归档 + 工具/标准/大师库 + Infoseek 锚点 + LLM 辅助
- 生命周期：新建 → 活跃 → 稳定 → 归档 → 淘汰

### 11.3 L4 末端触点盲点收敛

- 触发：QCM 协议层规则 + 工序级流程未覆盖末端触点
- 兜底：Infoseek 收敛 Level 4（深度 2-3）
- 输出：热词库 L3 写入（高置信度）+ 案例复用
- 资源：max_tokens=5000 · max_query=5 · timeout=30s

### 11.4 降级一致性原则

- 触发一致性：每级收敛触发 = QCM 颗粒度对应层
- 兜底一致性：每级收敛兜底 = Infoseek 对应深度
- 输出一致性：每级收敛输出 = QCM 4 形态对应级别
- 资源一致性：每级收敛资源受限于收敛深度

### 11.5 健康指标

- 热词覆盖率：L1 ≥80% · L2 ≥60% · L3 ≥30%
- 末端触点命中率：≥70%
- 同类问题复用率：≥50%
