# 输出层 · 评估报告（Assessment Report · V5.0+ 严格分离）

> **定位**：输出层 4 大形态之 ③ · 体系/治理水平评估 · 协议层依赖 §7 L4 组织治理 4 层 × N 维度 · Token ~120
> **V5.0+ 严格分离**：本模板**不复述**§7 4 层 × N 维度完整定义 · 仅引用评估结果与评分
> **核心用途**：让管理层 30 分钟内了解组织能力现状 · 季度/年度治理评审

---

## 1. 标准模板（V5.0+ 严格分离 · 5 段式 + 评分）

```markdown
# {评估对象} 治理评估报告（{评估周期}）

【路由】意图={意图} · 领域={领域} · 置信度={置信度}（如有歧义请纠正 · §14 场景路由判定）

【评估摘要】
- 评估对象：{组织/部门/项目}
- 评估周期：{周期}
- 评估维度：L4 组织治理 4 层 × N 维度（详见 action-orders.md §7）
- 总分：{总分}/100 · 等级：{优秀/良好/合格/不合格}
- 关键结论：{1-2 句话总结}

【现状评估】4 层 × N 维度评分

|------|---------|---------|---------|------|------|

【关键缺口】
- L4-{N} {层名}：{缺口描述}（评分差距 {差距}）
- L4-{N} {层名}：{缺口描述}
- L4-{N} {层名}：{缺口描述}

【改进建议】
- 短期（1 季度）：{改进动作 1}（责任：{责任层}）【R:{责任} · C:{配合} · I:{知会}】
```

## 3. 评分标准（L4 4 层 × N 维度）

| L 层 | 评分维度 | 0-5 分（基础）| 6-15 分（达标）| 16-25 分（优秀）|
|------|---------|------------|------------|--------------|
| **L4-① 战略层** | 风险偏好声明 + CMMI 组织目标 + 战略案例归档 | 缺失 | 部分（≥1项）| 全部（3 项 + 量化）|
| **L4-② 治理层** | 治理六层 + MP归口 + 审计增项 + 治理 SOP | 缺失 | 部分（≥2 项）| 全部（4 项 + RACI）|
| **L4-③ 执行层** | MES集成 + SOP v2 + 9 点路径 + 同工艺横向 | 缺失 | 部分（≥2 项）| 全部（4 项 + 自动化）|
| **L4-④ 回流层** | 场景库入库 + MDS 字段 + 工具注释 + 同型号横向 | 缺失 | 部分（≥2 项）| 全部（4 项 + 跨部门）|

**总分计算**：L4-① + L4-② + L4-③ + L4-④ = 100 分（每层满分 25）

## 4. 严格分离规则（V5.0+）

| 规则 | 内容 |
|------|------|
| ① | **不复述§7 4 层 × N 维度完整定义** · 仅引用评分维度 |
| ② | **不展开 MDS F1-F24 字段详情** · 仅引用字段编号 |
| ③ | **不展开 4×N 表格** · 仅引用评分结果 |
| ④ | **30 分钟评审支持** · 一份报告 = 一个治理评估 |
| ⑤ | **评分基于公开标准**（CMMI/ISO 9001/IATF 16949 等）· 不杜撰 |

## 6. 示例场景

```
# 某精密制造龙头 治理评估报告（2026 Q3）
【评估摘要】
- 评估对象：某精密制造龙头（消费电子功能件）
- 评估周期：2026 Q3
- 评估维度：L4 组织治理 4 层 × N 维度
- 总分：86/100 · 等级：良好
- 关键结论：L4-③ 执行层 MES 集成优秀，但 L4-④ 回流层场景库覆盖不足

【现状评估】
| L 层 | 当前评分 | 备注 |
|------|---------|------|
| L4-① 战略层 | 22/25 | 风险偏好+CMMI 量化目标完整 |
| L4-② 治理层 | 23/25 | 治理六层+RACI+审计齐全 |
| L4-③ 执行层 | 24/25 | MES+AOI+自动化防错全覆盖 |
| L4-④ 回流层 | 17/25 | 场景库覆盖率 70%（待提升）|

【关键缺口】
- L4-④ 回流层：场景库覆盖 70%，缺 3 个高频场景
【改进建议】
- 短期：补 3 个高频场景入库（质量经理）
- 中期：场景库覆盖率 ≥90%（集团质量部）
- 长期：场景库自动化入库机制（IT 部）
```

> **引用协议层**：action-orders.md §7 L4 组织治理 4 层 × N 维度 + §2.3 4 形态映射。

## 7. V6.1-6.3 增强契约（Phase 1+2+3）

### 7.1 输入契约（input_schema · V6.2）

```yaml
input_schema:
  type: object
  required:
    - evaluation_target (string)  # 评估对象（组织/部门/项目）
    - evaluation_cycle (enum)     # 季度/半年度/年度
    - evaluator (string)          # 评估方（内部/第三方）
  optional:
    - mds_fields (object)         # MDS F1-F24 部分字段
    - focus_layers (array)        # L4-①/②/③/④ 指定评估层
    - baseline_score (number)     # 上一周期评分（对比）
  validation:
    - evaluation_cycle ∈ {季度, 半年度, 年度}
    - focus_layers ⊆ {L4-①战略, L4-②治理, L4-③执行, L4-④回流}
```

### 7.2 输出契约（output_schema · V6.2）

```yaml
output_schema:
  type: object
  required:
    - form (string)                # "assessment_report"
    - evaluation_summary (object)  # 评估摘要（总分 + 等级）
    - layer_scores (array)         # 4 层 × 25 分
    - key_gaps (array)              # 关键缺口
    - improvement_plan (object)     # 短/中/长期改进
    - double_zero (string)         # 按动作阶段对照
    - followup_plan (string)       # 后续计划
  optional:
    - execution_trace (object)     # V6.3 新增
    - uncertainty_markers (array)
    - data_freshness (string)
    - side_effects (object)        # 评估报告有副作用（写历史）
  forbidden:
    - 财务预测
    - 个人评分（如对个人的绩效评分，应使用专门绩效系统）
    - 编造数据（必须基于实际观察/调研）
```

### 7.3 副作用声明（side_effects · V6.1）

```yaml
side_effects:
  changes: 评分记录写入 governance.md 历史（可追溯）
  rollback: 撤销历史记录（需管理员）
  idempotent: false (重复评分会覆盖历史)
  auto_retry: false
  data_pollution: 评分记录需保留（avoid重复评估浪费）
  state_pollution: governance.md 历史记录追加
  cleanup_skill: governance.history_management
  trigger_warning: 重复执行需提示用户
```

### 7.4 降级路径（V6.2）

| 输入完整性 | 输出策略 |
|----------|---------|
| **完整评估** | 4 层 × 25 分完整 + 关键缺口 + 改进建议 |
| **部分评估** | 仅评估 focus_layers 指定层 + 默认其他层 |
| **极简评估** | 仅总分 + 等级（基于已有数据）|
| **无数据** | 请求最小必要信息（评估对象 + 周期）|

### 7.5 边界声明（V6.1）

- **不适用场景**：单次危机应急（用决策卡片/快速响应）/ 实战案例（用案例应用）/ 个人绩效（用专业系统）
- **输出边界**：不复述 §7 4 层 × N 维度完整定义 / 不展开 5×5 双归零 / 不引用工具标准大师标签（除非评分依据）
- **Token 边界**：评估报告 ≤150 Token · 30 分钟评审支持

### 7.6 禁止内容清单（V6.2）

- 不得输出：财务预测 / 个人评分 / 编造数据 / 模糊评级（如"良好但需改进"无具体评分）
- 评分必须有依据（数据来源 / 观察记录 / 调研结果）
- 改进建议必须可执行（具体动作 + 责任主体 + 时间窗）

### 7.7 执行轨迹（execution_trace · V6.3）

```yaml
execution_trace:
  phase_1_anchor:
    inputs_received: [evaluation_target, evaluation_cycle, evaluator]
    protocol_matched: action-orders.md §7 (L4 4 层 × N 维度)
    output_form_matched: assessment_report (V6.0 P4)
  phase_2_compile:
    sections_filled: [评估摘要, 现状评估, 关键缺口, 改进建议, 双归零对照, 后续计划]
    field_count: 6 sections × 4-6 items = ~30 fields
    layer_scores: [L4-①战略, L4-②治理, L4-③执行, L4-④回流]
  phase_3_validate:
    output_validator_result: pending
    side_effects_declared: true (写历史)
    defensive_output_applied: true
    [unverified]_markers: ≥0 (评分依据标注)
  phase_4_deliver:
    output_token: ~120
    evaluation_cycle: 季度/半年度/年度
    side_effect_trigger: write_to_governance_history
```

### 7.8 [unverified] 标注规则（V6.2）

- **必须标注**：评分依据（如"基于 5 份内部调研"） / 第三方数据 / 推测评分
- **格式**：同案例应用 `[unverified]`

### 7.9 数据时效声明（V6.2）

```
数据时效：评估基于 {评估周期} 的实际数据。
治理记录：本评估写入 governance.md 历史（时间戳）。
趋势对比：与 baseline_score 对比（如有）。
```
